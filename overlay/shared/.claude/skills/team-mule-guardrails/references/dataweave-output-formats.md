# DataWeave output formats

Reference for [the DataWeave rules](../../../rules/dataweave.md). Read it before changing an `output` directive or its writer properties, or writing CSV or XML. Items marked (documented) are stated in MuleSoft documentation; items marked (CLI) were observed with the DataWeave CLI (runtime 2.12.2, language levels 2.4–2.9) and should be confirmed on the project's runtime when they decide the outcome.

- The CSV writer escapes separators, quotes and line breaks with `\` instead of quoting (`x\,y`) unless configured, and uses the system line separator. When a consumer expects quoted fields, `output application/csv quoteValues=true, escape="\"", lineSeparator="\r\n"` wrote `"x,y"`, doubled embedded quotes and used CRLF line endings; it also quotes numbers and writes null as `""` (CLI). Separate writer properties with commas, and test against the consumer. Quote escaping changed at language level 2.5: at 2.4 embedded quotes were written unescaped (CLI). See [CSV format](https://docs.mulesoft.com/dataweave/2.9/dataweave-formats-csv).
- The XML writer writes `null` and `""` as the same empty element (CLI). If they must differ, follow the project's convention; `writeNilOnNull=true` writes `xsi:nil="true"` for null (CLI). See [XML format](https://docs.mulesoft.com/dataweave/2.9/dataweave-formats-xml).
- JSON: preserve null versus omitted fields; `skipNullOn` changes the output contract and can change array positions (`[1, null, 3]` becomes `[1, 3]`). Duplicate keys, for example from repeated XML elements, are written as repeated JSON keys; `duplicateKeyAsArray=true` collects them into one array when the contract wants that shape. See [JSON writer options](https://docs.mulesoft.com/dataweave/2.9/dataweave-formats-json).
